# Домашнее задание №1

## Описание задачи
В прошлом семестре я разрабатывал приложение для автоматической генерации документов. На вход подаются файлы с таблицами, метаданными шрифта, дополнительно данные подтягиваются из сетевых источников, после чего генерируется пакет документов. 
Конечный пользователь - один менеджер, который будет работать с приложением на своем рабочем ноутбуке MacBook.

## Описание решений
Было рассмотрено 4 варианта реализации:
1. **CLI-инструмент** (консольная утилита).
2. **Desktop-приложение** (на базе Python и PySide6).
3. **Web-приложение** (генерация происходит на удаленном сервере).
4. **Приложение с web-интерфейсом** (развертывается локально в Docker-контейнере, генерация происходит на машине пользователя).

## Описание требований
К решению предъявлялись следующие жесткие требования:
- **Качество:** Генерация валидных документов с корректными данными.
- **Совместимость:** Бесперебойная работа на конкретном устройстве пользователя (MacBook).
- **UX/UI:** Простое и понятное в использовании (пользователь - менеджер, а не разработчик).
- **Безопасность:** В процессе работы используются чувствительные данные, которые категорически нельзя передавать или хранить на сторонних серверах.
- **Производительность:** Генерация одного пакета документов должна занимать не более 5 секунд.

## Почему было принято именно это решение?
Я выбрал **Desktop-приложение** на базе **PySide6**, так как оно обеспечивало лучший tradeoff (баланс) между сложностью реализации и удовлетворением всем требованиям.

**Почему это решение подходит:**
- **Безопасность:** Приложение работает локально, чувствительные данные не покидают устройство пользователя.
- **UX и стек:** PySide6 позволил создать нативный, отзывчивый интерфейс. Пользователю не нужно открывать терминал, можно один раз сохранить настройки локально и просто нажимать кнопку «Сгенерировать».
- **Совместимость (MacBook):** Так как у меня самого Linux, я решил проблему отсутствия Mac-устройства для сборки. Я настроил пайплайн CI, который автоматически собирал артефакт (через PyInstaller) под macOS и выгружал готовый файл.

**Почему были отклонены другие варианты:**
- **CLI-инструмент:** Технически это самый простой и быстрый вариант, но он абсолютно неудобен для конечного пользователя - менеджера.
- **Web-приложение:** Главная проблема — безопасность. Так как хранить чувствительные данные на сервере нельзя, их пришлось бы каждый раз загружать туда и обратно, что создает риски утечки. (Этот вариант подошел бы, если бы сервисом пользовалась большая команда).
- **Web-интерфейс в контейнере:** Хороший вариант с точки зрения разработки (у меня был опыт создания подобного на FastHTML), и настройки хранились бы локально. Однако необходимость для менеджера самостоятельно поднимать Docker-контейнер делает этот инструмент слишком сложным в эксплуатации.
